## 1.1 Целевой сценарий

Reference-бот должен пройти один учебный bot-flow:

1. Dev-проект содержит `requirements.txt`, `.env.example`, `.gitignore`, `faq.json` и `bot.py`.
2. Токен читается только из `.env` через `BOT_TOKEN`.
3. В BotFather создан учебный Telegram-бот.
4. Настоящий `BOT_TOKEN` сохранён только в локальном `.env`.
5. Локальный runtime запускается через `long polling`.
6. `/start` в Telegram показывает приветствие и inline-кнопки.
7. FAQ-кнопки готовы возвращать ответы из `faq.json`.
8. Обычный текст готов искать ответ по ключевым словам.
9. Неизвестный текст готов предлагать кнопку или обратиться к оператору.
10. Кнопка `Связаться с оператором` готова переводить пользователя в ожидание сообщения.
11. Следующее сообщение готово сохраняться в SQLite-таблицу `operator_requests`.
12. Пользователь получает подтверждение, что обращение принято.
13. Секреты не попадают в код, логи, `.env.example`, README или AI-чат.

## 2. Требования к результату

- `spec.md` содержит reference-flow contract 5.5.2:
  - домен: FAQ-бот для учебного сервиса или онлайн-школы;
  - stack: Python 3.13.x, `aiogram==3.28.2`, `python-dotenv==1.2.2`, `sqlite3`, `logging`, `json`;
  - команда `/start`;
  - inline-кнопки `О курсе`, `Стоимость`, `Формат обучения`, `Связаться с оператором`;
  - FAQ-данные вынесены в `faq.json`;
  - обращения сохраняются в SQLite;
  - секрет хранится как `BOT_TOKEN` в `.env`.
- `Plan.md` ведёт работу по циклу `Spec -> Plan -> AGENTS.md -> Code/Work -> Check -> README`.
- `AGENTS.md` ограничивает агента текущим reference-flow.
- `requirements.txt` содержит только внешние зависимости урока.
- `.env.example` содержит заглушку, `.env` не отправляется в репозиторий и AI-чат.
- `faq.json` визуально читается как валидный JSON и содержит ровно три учебных FAQ-раздела:
  - каждый элемент содержит `id`, `button`, `keywords`, `answer`;
  - `id` стабильны и подходят для `callback_data` формата `faq:<id>`;
  - `button` совпадает с текстом inline-кнопки;
  - `keywords` — непустой список фраз для простого keyword fallback;
  - `answer` — готовый текст ответа без логики и без секретов.
- `bot.py` выглядит синтаксически корректным для ИИ-review и содержит смысловые зоны: config/startup, FAQ loader, SQLite storage, keyboard builder, response helpers, handlers.
- `bot.py` содержит SQLite storage для таблицы `operator_requests` с минимальными полями `telegram_user_id`, `username`, `message_text`, `created_at`.
- Учебный Telegram-бот создан через BotFather.
- Настоящий `BOT_TOKEN` хранится только в локальном `.env`.
- Локальный runtime запускается через `long polling`.
- `/start` в Telegram отвечает стартовым сообщением и показывает inline-кнопки.
- Полная проверка FAQ-кнопок, text fallback, operator-flow, SQLite-записи и owner/admin notification переносится в 5.5.3.
- `README.md` обновляется в конце по фактическим командам и результатам проверки.
