# AGENTS.md — reference_faq_bot

## Контекст проекта

- Проект: локальный учебный FAQ reference-бот для онлайн-школы.
- Текущая фаза: `5.5.2 simplified reference bot`.
- Цель фазы: собрать проверяемый скелет `handler -> response -> SQLite`, создать учебного BotFather-бота и подтвердить `/start` через локальный `long polling`.
- Основные файлы: `spec.md`, `Plan.md`, `AGENTS.md`, `requirements.txt`, `.env.example`, `.env`, `.gitignore`, `faq.json`, `bot.py`, `README.md`.

## Источники истины

- Перед кодом читать `spec.md`, reference-flow contract и активный пункт `Plan.md`.
- `Plan.md` хранит текущий шаг, проверки, ошибки и следующий узкий запрос.
- `README.md`  использовать как источник фактических команд.
- Версии зависимостей брать из `requirements.txt` и `spec.md`, а не придумывать по памяти.
- Реальный `.env` не читать, не печатать и не просить прислать в чат.
- BotFather-действия выполняет студент в Telegram UI; агент может формулировать безопасные шаги, но не должен видеть token.

## Рабочие правила

- Выполнять один активный пункт `Plan.md` за раз.
- Перед изменением файлов показывать список файлов и план изменений.
- После каждого фрагмента обновлять статус, проверки и ошибки в `Plan.md`.
- Финальный `README.md` обновлять после проверенного результата, а не до кода.
- Если ошибка связана с токеном, объяснять симптом без запроса реального секрета.

## Правила bot-flow


- Использовать Python 3.13.x, `aiogram==3.28.2`, `python-dotenv==1.2.2`, `sqlite3`, `logging`, `json`.
- Токен читать только из `BOT_TOKEN` через `.env`.
- FAQ-ответы читать из `faq.json`.
- `/start` показывает приветствие и inline-кнопки.
- FAQ callbacks возвращают ответы из JSON.
- Обычный текст ищет FAQ по ключевым словам.
- Неизвестный текст предлагает выбрать кнопку или связаться с оператором.
- Flow `Связаться с оператором` сохраняет одно сообщение в SQLite.
- SQLite хранит только `telegram_user_id`, `username`, `message_text`, `created_at`.
- Один простой `bot.py` допустим для reference-урока, но код должен быть размечен по смыслу: config, FAQ, storage, keyboard, handlers, startup.

## Секреты и данные

- Не вставлять реальный token в `bot.py`, `faq.json`, README, логи или промпты.
- `.env.example` содержит только заглушку.
- `.gitignore` исключает `.env` и `requests.sqlite3`.
- Не собирать телефон, email, платежные данные, историю переписки и лишнюю аналитику.
- После BotFather настоящий token хранить только в локальном `.env`.
- Проверка `/start` в Telegram выполняется без публикации token и без скриншотов с секретами.

## Вне текущей фазы

- Не добавлять `owner/admin chat id` и уведомление владельцу.
- Не проходить полный FAQ/fallback/operator/SQLite-check; это старт 5.5.3.
- Не добавлять VPS, webhook, автоперезапуск, backup, incident flow или deploy.
- Не добавлять API ИИ, AI-агента, CRM, оплату, web-админку и полный финальный project flow.
